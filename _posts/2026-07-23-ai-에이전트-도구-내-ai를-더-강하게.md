"AI 챗봇"과 "AI 에이전트"의 차이가 뭘까? 이번 챕터에서 이 구분이 명확해졌다. 그리고 에이전트를 더 강력하게 만드는 도구들을 알게 됐다.

---

## 챗봇 vs 에이전트

둘 다 AI이긴 한데, 하는 일의 범위가 다르다.

| 구분 | 챗봇 | 에이전트 |
|------|------|---------|
| 하는 일 | 질문에 답한다 | 목표를 받아서 스스로 판단하고 실행한다 |
| 주도권 | 사람이 매번 지시 | AI가 중간 단계를 알아서 결정 |
| 도구 사용 | 대화만 | 파일 읽기, 코드 실행, 외부 서비스 호출 |
| 비유 | 안내 데스크 직원 | 프로젝트 매니저 |

챗봇에게 "브랜드 리뉴얼 해줘"라고 하면 방법론을 설명해준다. 에이전트에게 같은 말을 하면, 경쟁사 조사 → 키워드 정리 → 컨셉 도출 → 시안 생성까지 순서를 잡아 하나씩 실행한다. 중간에 막히면 스스로 방향을 바꾸기도 한다.

핵심 차이는 **행동력**이다. 에이전트는 대화를 넘어서 **실제로 무언가를 한다**.

## MCP — AI가 세상과 연결되는 통로

MCP(Model Context Protocol)는 에이전트가 외부 도구를 사용할 수 있게 해주는 **연결 규격**이다.

AI가 아무리 똑똑해도, 혼자서는 파일을 열거나 웹을 검색하거나 데이터베이스에 접속할 수 없다. MCP는 이런 외부 기능을 **표준화된 방식으로** 연결해주는 다리 역할을 한다.

비유하자면 USB-C 같은 것이다. 충전기, 모니터, 외장하드가 다 다른 제품이지만 USB-C 규격을 따르면 하나의 포트에 연결할 수 있듯, MCP를 따르면 다양한 외부 서비스를 AI에 붙일 수 있다.

### 실제로 가능한 것들

MCP로 연결할 수 있는 외부 도구의 예시:
- **파일 시스템**: 로컬 폴더의 파일을 읽고 쓰기
- **GitHub**: 코드 저장소에서 파일 검색, 이슈 확인
- **Slack/Notion**: 메시지 보내기, 문서 조회
- **데이터베이스**: Supabase 등의 DB에 직접 쿼리
- **웹 검색**: 실시간 정보 검색

이전에는 각 서비스마다 별도의 연동 코드를 짜야 했다면, MCP가 있으면 **설정 한 번으로** 연결이 끝난다.

## Skills와 AGENTS.md — AI에게 일하는 방식을 가르치기

에이전트에게 도구를 줬으면, 이제 **어떻게 일할지** 알려줘야 한다.

### Skills

스킬은 반복적으로 사용하는 작업 패턴을 미리 정의해두는 것이다. 매번 "이전에 이야기한 것처럼..."이라고 설명하는 대신, 한 번 정리해두면 이름만 불러서 실행할 수 있다.

디자인 업무에 비유하면, Figma에서 자주 쓰는 작업을 컴포넌트로 만들어두는 것과 같다. "명함 레이아웃" 컴포넌트를 만들어두면 매번 가이드라인을 처음부터 설명할 필요 없이, 인스턴스만 꺼내 쓰면 된다.

### AGENTS.md

AGENTS.md는 프로젝트 루트에 두는 파일로, **AI가 이 프로젝트에서 어떻게 행동해야 하는지**를 적어둔 매뉴얼이다.

포함할 수 있는 내용:
- 코드 스타일 규칙 ("함수명은 camelCase로")
- 프로젝트 구조 설명 ("API 코드는 /api 폴더에")
- 금지 사항 ("이 파일은 수정하지 마")
- 작업 절차 ("변경 후 반드시 테스트 실행")

새 팀원에게 주는 온보딩 문서와 같은 역할이다. 이게 잘 작성되어 있으면 AI가 프로젝트의 맥락을 이해한 상태로 일하기 때문에, 매번 같은 설명을 반복하지 않아도 된다.

## 코딩 하네스 비교 — 어떤 도구로 바이브 코딩할까

"하네스(harness)"란 AI를 사용해서 코딩하는 환경을 말한다. 같은 AI 모델이라도 어떤 하네스로 쓰느냐에 따라 작업 방식과 결과가 달라진다.

### 주요 하네스 비교

| 하네스 | 특징 | 적합한 상황 |
|--------|------|------------|
| **Claude Code** | 터미널 기반, 파일 직접 조작 가능, MCP 연결 지원 | 전체 프로젝트를 자율적으로 작업 |
| **Cursor** | VS Code 기반 에디터에 AI 내장, 코드 맥락 이해도 높음 | 기존 코드를 수정하며 개발 |
| **Windsurf** | Cursor와 유사, 멀티파일 편집에 강점 | 여러 파일을 동시에 다루는 작업 |
| **ChatGPT/Claude 웹** | 대화 기반, 코드 블록 복사-붙여넣기 방식 | 단편적인 코드 질문, 학습 |
| **v0/bolt** | 프롬프트로 UI를 바로 생성 | 프론트엔드 프로토타이핑 |

### 에이전트형 vs 어시스턴트형

하네스는 크게 두 부류로 나뉜다.

**어시스턴트형** (ChatGPT 웹, Copilot 자동완성): 사람이 주도하고 AI가 부분적으로 돕는다. 한 줄, 한 블록 단위로 제안한다.

**에이전트형** (Claude Code, Cursor Agent 모드): AI가 목표를 받으면 여러 파일을 오가며 스스로 작업한다. 실행 → 에러 확인 → 수정을 반복한다.

바이브 코딩은 **에이전트형** 하네스와 궁합이 좋다. "이 기능 만들어 줘"라고 하면 AI가 파일 생성부터 테스트까지 흐름을 이어가기 때문이다.

### 고르는 기준

어떤 하네스가 최고냐보다, **내 상황에 맞는 걸 고르는 게** 중요하다.

- 터미널이 익숙하다면 → Claude Code
- 에디터에서 바로 작업하고 싶다면 → Cursor / Windsurf
- 코드보다 화면을 빨리 보고 싶다면 → v0 / bolt
- 개념 이해나 학습이 목적이라면 → 웹 채팅

나는 이 블로그 자체를 Claude Code로 만들고 운영하고 있어서 자연스럽게 Claude Code를 주력으로 쓰고 있다.

## 디자이너의 시각

이 챕터를 듣고 느낀 건, **AI 에이전트 도구를 세팅하는 일이 디자인 환경을 세팅하는 것과 똑같다**는 것이다.

| 디자인 환경 세팅 | AI 에이전트 세팅 |
|----------------|-----------------|
| Figma 플러그인 설치 | MCP로 외부 도구 연결 |
| 디자인 시스템 라이브러리 등록 | Skills 정의 |
| 팀 온보딩 문서 작성 | AGENTS.md 작성 |
| Figma vs Sketch vs XD 선택 | Claude Code vs Cursor vs v0 선택 |

도구를 잘 세팅해두면 매 프로젝트마다 처음부터 설명할 필요가 없어진다. 처음에 시간을 투자해서 환경을 잡아두면, 이후의 모든 작업이 빨라지는 건 디자인이든 코딩이든 마찬가지다.
