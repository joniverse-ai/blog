지금까지 만든 AI 친구 하루는 웹 서비스였어. 오늘은 이걸 **내 폰에 앱으로** 가져갔어.

아침엔 솔직히 겁먹었어. 앱이면 Swift니 Kotlin이니 새 언어를 배워야 하고, Xcode 같은 무거운 도구도 깔아야 하는 거 아닌가? 끝나고 보니 새로 만든 건 **화면뿐**이었어.

---

## 웹과 앱, 뭐가 다를까

웹은 주소를 열 때마다 서버에서 화면을 새로 받아. 그래서 고치면 모두가 바로 새 화면을 봐.

앱은 폰에 **설치해 두고** 실행해. 고친 화면은 사용자가 업데이트해야 닿고, 업데이트 안 한 폰에는 **옛 버전이 계속 남아.** 그래서 앱이 쓰는 API는 응답 모양(필드 이름)을 함부로 바꾸면 안 된대. 옛 앱이 옛 이름을 찾다가 화면이 깨지니까.

디자이너 말로 하면, 웹은 **바로 고치는 디지털 배너**고 앱은 **이미 뿌린 인쇄물**이야. 회수가 안 돼.

---

## 왜 Expo였나

폰으로 가져가는 방법은 네 가지였어.

| 방법 | 화면을 그리는 것 | 한 줄 평 |
|---|---|---|
| PWA | 브라우저 | 가볍지만 기기 기능과 스토어에 한계 |
| 웹 래핑 | 앱 안의 브라우저 창 | 웹 그대로, 느낌도 웹 |
| 네이티브 | 폰 기본 부품 | 아이폰용, 안드로이드용을 따로 |
| **React Native + Expo** | 폰 기본 부품 | **노트북에 Node.js만** 있으면 됨 |

Expo는 일을 이렇게 나눠.

- 카메라, 사진첩 같은 네이티브 부분은 **Expo Go** 앱에 미리 들어 있어.
- 내 코드는 노트북 개발 서버에서 폰으로 바로 보내.
- 진짜 앱 파일은 나중에 **EAS**가 클라우드에서 만들어 줘(이건 내일).

QR 하나 찍으니까 내 폰에서 하루가 열렸어. 코드를 저장하면 몇 초 만에 폰 화면이 바뀌는 게 신기하더라.

---

## 앱은 화면, 백엔드는 두뇌

앱이 알고 있는 건 **백엔드 주소 하나**야. 나머지는 다 백엔드한테 물어봐.

```
설정 받기 → 게스트로 로그인 → 내 정보 → 캐릭터 → 지난 대화 → 대화(스트리밍)
```

재밌었던 점: 같은 서버인데 **폰과 브라우저는 서로의 대화가 안 보여.** 둘이 로그인 정보를 따로 저장해서 서로 다른 게스트가 되거든. 서버가 모든 조회에 "로그인한 사람" 조건을 붙이니까 각자 자기 것만 보여. 데이터가 사라진 게 아니야.

---

## 오늘 만든 기능: 사진으로 약속 만들기

종이 일정표를 **폰으로 찍으면** 하루가 날짜와 시각을 읽고, 약속으로 저장해 주는 기능이야. 앱으로 만든 이유가 제일 잘 드러나는 기능이었어.

![사진으로 약속 만들기에서 앱과 백엔드가 나눈 일]({{ "/assets/img/2026-11-05/app-backend-split.svg" | relative_url }})

- 앱은 **사진 받기, 권한 묻기, 보내기**까지만 해.
- 글자를 읽고 약속을 만드는 건 백엔드가 해.
- AI 키나 DB 비밀 키 같은 건 **앱에 하나도 없어.** 앱 파일은 누구나 뜯어볼 수 있거든.

읽은 글을 **바로 보내지 않고** 입력창에 넣어 두는 게 포인트야. 글자 읽기가 날짜를 틀리면 엉뚱한 시각에 알림이 가니까, 사람이 한 번 보고 고치게 했어. 자동 번역본을 납품 전에 교정 보는 거랑 같아.

답 아래에는 회색 글씨로 `🧠 기억했어요`, `⏰ 약속` 메모도 붙였어. 근데 앱을 다시 열면 이 메모는 사라져. 저장된 대화가 아니라 그 순간에 흘러온 알림이라서. 회의 중 **포스트잇이 회의록에 안 남는** 것과 같아.

---

## "너무 느려" 의 진짜 범인

여기가 오늘의 하이라이트였어.

카메라로 찍어 보냈더니 처음엔 이상한 영어 오류가 떴어. 알고 보니 이번 Expo 버전(SDK 58)이 앱의 통신 부품을 통째로 바꿔서, 예전 방식으로 사진을 보내면 거절하는 거였어. 교안에도 없던 함정이야. 고쳤더니 이번엔 "읽는 중…"에서 끝나질 않았어.

"글자 읽는 엔진이 느린가 보다, 엔진 바꾸자!" 하고 마음먹었는데, Claude가 먼저 서버 기록을 봤어.

![OCR이 느리다는 증상을 따라간 과정]({{ "/assets/img/2026-11-05/slow-ocr-story.svg" | relative_url }})

**서버에 사진 요청이 0건.** 엔진은 사진을 받아 본 적도 없었던 거야. 범인은 폰이었어. 사진을 앱 코드로 묶는 단계에서 멈춰 있었고, 폰의 기본 업로드 기능에 맡기니까 해결됐어.

그런데 덤으로 찾은 게 있어. 원래 엔진(tesseract)은 0.5초로 빨랐는데, 깨끗한 컴퓨터 글씨인 "11월 20일"을 `NS 208`로 읽더라. 그래서 엔진은 **속도가 아니라 정확도 때문에** 바꿨어.

- **Google Cloud Vision**으로 교체 → 서버에서 0.3~0.6초, 날짜까지 정확하게.
- 인증은 서버 계정의 임시 토큰이라 **키 파일 자체가 없어.**
- 엔진을 통째로 바꿨는데 **앱은 한 줄도 안 바꿨어.** 아까 그림의 "앱은 화면, 백엔드는 두뇌"가 이거였어.

"느리다"는 증상이지 원인이 아니라는 걸 배웠어. 엔진부터 갈아 끼웠으면 돈과 시간만 쓰고 폰에선 여전히 안 됐을 거야.

## 디자이너의 눈으로 다시 보면

| 오늘 배운 것 | 디자인으로 치면 |
|---|---|
| 웹 vs 앱 | 디지털 배너 vs **이미 배포된 인쇄물** |
| API 응답 모양 유지 | 옛 브로슈어의 QR이 가리키는 **주소를 지우지 않기** |
| Expo Go | 부품이 다 들어 있는 **목업 키트**에 내 디자인만 끼워 보기 |
| 앱은 화면, 백엔드는 두뇌 | 매장 진열(앱)은 바꿔도 **창고와 재고 시스템**(백엔드)은 그대로 |
| 사람이 확인하는 단계 | 자동 번역본 **교정** |
| 요청 0건 확인 | 인쇄가 이상하면 잉크 탓하기 전에 **파일이 인쇄소에 도착했는지**부터 |

## 아직 남은 것

- 지금 앱은 **내 노트북 개발 서버가 켜져 있을 때만** 열려. 다른 사람 폰에는 못 깔아. → 내일 EAS로 진짜 앱 파일 만들기.
- 앱 고유 이름(Bundle ID)이 아직 템플릿 기본값이야. 스토어에 올리면 못 바꾸니까 내일 정해야 해.
- 답 아래 메모를 지난 대화에도 남기려면 백엔드가 저장해야 해.
- 운영 서버에도 Vision을 켤지, 켠다면 "사진은 글자 읽기에만 쓰고 저장하지 않아요" 안내를 어디에 넣을지.
